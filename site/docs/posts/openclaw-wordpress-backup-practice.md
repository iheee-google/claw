# OpenClaw + WordPress：把“能跑”变成“稳跑”的备份实践

这篇记录我在云服务器上为 WordPress 做自动备份的完整实践：不仅要“备份成功”，还要“可恢复、可追踪、可持续”。

## 目标

- 每天自动备份数据库和 uploads
- 保留 14 天，自动清理过期
- 有日志可查，出问题能排查

## 落地方案

- 备份脚本：/usr/local/bin/wp_backup_daily.sh
- 备份目录：/var/backups/wordpress
- 计划任务：每天 03:30 运行
- 日志：/var/log/wp_backup.log

## 为什么这套方案稳
核心不是“备份一下”，而是把备份流程固化成系统行为。脚本 + cron + 日志 + 保留策略，才是可长期运行的闭环。

## 下一步建议

- 每周做一次恢复演练（抽样恢复）
- 增加异地备份（对象存储）
- 备份失败主动告警

一句话：备份不是仪式感，是生产能力。

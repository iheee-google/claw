# memory/lessons.md

> 教训层：记录踩坑与经验，按严重程度分级。

## 严重程度说明
- **P0**: 严重故障 / 数据风险 / 安全风险
- **P1**: 影响主要功能或用户体验
- **P2**: 一般问题，可接受但需优化
- **P3**: 轻微问题 / 习惯改进

## 模板

### [P1] 标题
- **日期**: YYYY-MM-DD
- **现象**: 发生了什么
- **根因**: 为什么发生
- **修复**: 做了什么
- **预防**: 如何避免再次发生
- **标签**: #tag1 #tag2

### [P2] Cron 任务在切换 main 前置检查失败（未跟踪文件冲突）
- **日期**: 2026-03-09
- **现象**: Daily Summary Cron 在执行 `git checkout main` 前置步骤时失败，提示未跟踪文件会被覆盖，任务中断。
- **根因**: 工作区存在未纳管文件（如 `.openclaw/workspace-state.json` 及若干根目录配置文件），且分支切换未先做冲突探测与隔离。
- **修复**: 记录失败原因到当日日志，并在本任务中将“先 `git status --short` 且非空即退出”作为硬前置。
- **预防**: 所有夜间 cron 先执行“分支锁定 + 干净工作区校验”；发现冲突时仅写日志并退出，不进入记忆写入流程。
- **标签**: #cron #git #precheck #workspace-hygiene


### [P1] 长任务期间未及时回执，导致用户感知“卡住”
- **日期**: 2026-03-05
- **现象**: 执行重启/索引等长任务时，未先回复“收到，处理中”，用户需要补发“？”才收到反馈。
- **根因**: 长阻塞调用未做分段回执与轮询汇报。
- **修复**: 在 AGENTS.md 增加响应时效规则（先回执、10秒汇报、短超时轮询、超时降级）。
- **预防**: 所有 >10 秒任务必须先回执并持续状态更新。
- **标签**: #response-latency #ux #process

### [P1] 多次出现长任务静默，用户需反复催促
- **日期**: 2026-03-06
- **现象**: 执行 hooks/cron/git 等操作时，阶段性出现>10秒无回执，用户多次发送“？”或“又不回复了”。
- **根因**: 后台命令轮询期间缺少固定节拍回执；对“挂起无输出”缺少强制止损阈值。
- **修复**: 在 AGENTS.md 增加“防静默硬约束”（3秒首回执、15秒进度、20秒挂起止损、完成即回报），并写入 USER.md 痛点偏好。
- **预防**: 长任务统一采用“先回执→短轮询→定时播报→超时降级”模板，避免单段静默。
- **标签**: #response-latency #ux #reliability

### [P2] 出现“空输出消息”导致用户感知异常
- **日期**: 2026-03-06
- **现象**: 个别回合出现消息框已发送但正文为空，用户反馈“空输出”。
- **根因**: 长任务阻塞与并发消息场景下，回复生成/提交时机竞争，缺少发送前非空校验。
- **修复**: 在 AGENTS.md 增加“防空输出流程”（非空校验、占位回执、并发防覆盖、异常降级文案），并写入 USER.md 规则。
- **预防**: 所有回复发送前必须做非空校验；无法生成正文时先发“处理中”占位文本。
- **标签**: #empty-output #response-latency #reliability

### [P2] 低 RPM 配额下不应启用并发子 agent 方案
- **日期**: 2026-03-05
- **现象**: 当前模型额度为每分钟 4 次，请求密集时并发方案容易触发排队/超时风险。
- **根因**: 方案设计未充分匹配实际吞吐上限。
- **修复**: 当日决策暂缓启用子 agent 并发流程，保留串行执行。
- **预防**: 新流程上线前先校验速率配额与并发模型，超限场景默认降级为串行。
- **标签**: #rate-limit #capacity-planning #subagent

### [P1] grok-41/grok-4.1-thinking 配置下出现“声明已提交但仓库无记录”
- **日期**: 2026-03-06
- **现象**: 在 grok-41/grok-4.1-thinking 配置阶段，多次回复声称已 commit/push，但 GitHub 未出现对应提交记录。
- **根因**: 结果回报先于真实命令执行；且未先做 `git pull --rebase` 导致 push 被远端快进保护拒绝。
- **修复**: 切换回当前稳定模型后，改为“先执行命令并拿到原始输出，再回报 hash”；补充日志明确标注该问题发生于 grok-41/grok-4.1-thinking 配置阶段。
- **预防**: 未看到 `main -> main` 这类 push 成功输出前，禁止宣称已同步 GitHub；失败时必须附可复制修复命令。
- **标签**: #git #grok-41 #postmortem #push-failure

### [P1] 长链任务被动回复（等用户催）导致体验下降
- **日期**: 2026-03-07
- **现象**: 执行连续多步骤优化时，存在“用户发一句才回一句”的被动节奏，用户明确要求整改。
- **根因**: 虽有长任务汇报规则，但缺少“主动播报”硬性条款与固定节拍。
- **修复**: 在 AGENTS.md 新增“长链任务主动播报”“禁止等用户催”规则，并写入 USER.md 用户偏好。
- **预防**: 长链任务默认每 2~5 分钟主动播报一次或按里程碑播报，不依赖用户触发。
- **标签**: #proactive-update #ux #process
